2. UnlockBuffer

В логе накоплено 2 751 429 одинаковых записей (510.715 МиБ). Раньше равенство
определялось после Lock/memcpy/Unlock. Теперь производственный Replayer
может пропустить такую загрузку заранее по существующей достоверной
CPU-копии ровно этого буфера. Нового кеша, readback или аллокации нет.
Доступны оба командных пути: UnlockBuffer и UnlockBufferRef.

Условия допуска: статический буфер с flags=0 либо DEFAULT/DYNAMIC с
NOOVERWRITE; точное совпадение диапазона и байтов, безопасная версия,
отсутствие незавершённых блокировок, действующая полная CPU-копия.
Динамический flags=0 и любой DISCARD всегда доходят до драйвера: они
задают границу синхронизации/переименования для будущего NOOVERWRITE.
См. контракт Microsoft:
https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dlock
https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3dvertexbuffer9-lock

После частичного DISCARD байты вне диапазона неопределены. Копия больше
не доказывает равенство будущей записи, пока не выполнена полная запись
или полное чтение. Это также закрывает прежнюю возможность восстановления
старой версии по устаревшим байтам CPU-копии.

Оптимизация привязана к точному объекту, указанному UnlockSourceScope;
вложенная запись другого буфера не может использовать чужой источник.
Обычные Lock/Unlock без явного разрешения Replayer сохраняют контракт.
Ошибки Unlock теперь учитываются в replayFailures.

Три одинаковых офлайн-прогона, по 28 160 вызовов каждого варианта на прогон.
Каждый буфер: восемь блоков ABBAABBA по 32 записи, диапазоны 256/65536 байт,
ограниченные размером буфера. CPU submit, суммарно по 84 480 вызовам:
  Статические: 97.5492 -> 49.9736 мс (-48.8%).
  Динамические NOOVERWRITE: 351.9656 -> 48.4103 мс (-86.2%).
Время с ожиданием завершения GPU, включая CPU submission:
  Статические: 291.7147 -> 205.0425 мс (-29.7%).
  Динамические: 612.3782 -> 201.3503 мс (-67.1%).
Это искусственная последовательность одинаковых записей реальной геометрии,
а не запись команд игры. Она измеряет подходящие для пропуска загрузки;
частота таких случаев в игре и выигрыш FPS этим тестом не устанавливаются.

Новая строка CSTREAM UPLOAD разделяет Lock / memcpy / Unlock, показывает
максимум каждой стадии, байты, пропуски и ошибки. Измеряется только при
Diagnostics на прежних кадрах 1/127; на обычных кадрах дополнительных
чтений часов нет. BUFFER content дополнен skippedWrites/skippedMiB.
Старый лог не разделяет стадии выброса UnlockBuffer 5.6204 мс, поэтому
устранение всех таких задержек пока не доказано; новые поля позволяют
проверить причину по следующему пользовательскому логу.

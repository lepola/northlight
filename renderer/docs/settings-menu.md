# In-game settings

Northlight draws its own settings window inside the game, in the renderer DLL, over the finished frame. Toggle it with Ctrl+Shift+F11. The window takes mouse and keyboard input only while the cursor is over it or a text field is active; the hotkey never reaches the game. Nothing in this feature calls, reads or patches the game client, and there is no addon or CVar. `[Renderer] SettingsOverlay=0` in `northlight-renderer.ini` turns the window off completely (read at device creation). `[Renderer] SettingsOverlayKey=Ctrl+Shift+F11` changes the toggle: F1 to F12 with any of Ctrl, Shift and Alt (matched exactly; Ctrl+Shift+F7 to F10 and F12 stay the renderer's own keys). An unusable value keeps Ctrl+Shift+F11 and says so once in `northlight-renderer.log`. Closing the window keeps unsaved edits and their live preview; a small line in the lower left corner then says so until you save or revert.

Edits are a draft. A live ("F") setting previews immediately and writes nothing; Save commits, Revert discards the draft and returns the renderer to the saved configuration. Settings marked "R" (restart required) are saved but only read at start-up: the command stream, worker and GI solver settings, NameMask, SpellLayer, backend and regional shadow range. Everything the menu shows comes from the same schema the renderer loads; unavailable controls are greyed out.

Saving is transactional. A worker thread preserves unknown INI lines, comments, UTF-8/UTF-16LE encoding and line endings, verifies the file revision before writing, serializes writers with an interprocess lock, and journals the multi-file commit so a crash is rolled back at the next start (before any INI is read). A read-only or externally edited file is reported by name and never overwritten. Saved and previewed live values reach the renderer at a frame boundary.

The in-process API is `NorthlightSettings::Service` (`src/settings/settings_service.h`): `requestSnapshot`/`snapshot`, `preview`/`clearPreview` (latest draft wins), `commit`, `status`. All calls are non-blocking; the worker does every file access.

The integrated build also exposes M2 material modes, terrain/object and model displacement controls, AO Quality, and the common cavity/self-shadow distance. Material mode lists include Displacement + normals where supported; grass retains its two supported modes. Equipment lights apply live at the frame boundary. HDR output is available in this build: enabling it needs a restart, while white levels, contrast and exposure preview live. The Renderer & HDR page reports the actual output status, and the overlay uses the configured UI white in scRGB output.

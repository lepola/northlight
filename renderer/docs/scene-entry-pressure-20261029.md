# Scene entry under address-space pressure, 2026-10-29

Request 1785 at Northrend `(5139.84, -56.93, 380.31)` was deferred at about 307 MiB free x86 virtual address space. Its 392 MiB entry requirement was the 256 MiB process reserve plus a 136 MiB working allowance. The reported 0.08 MiB capacity belonged to an attempt that had not built the scene. Lowering that gate alone would have exposed overlapping preparation, source caches, material copies and finished upload vectors.

The pressure path keeps the 256 MiB reserve and admits entry at 304 MiB (48 MiB working allowance). It omits optional source/BLAS caches, preserves the cropped geometry and ray semantics, and uses private `std::tmpfile` storage for disposable terrain/index work and finished pages. Each scratch array has four 64 KiB cache slots; no whole backing file is mapped. I/O, overflow, short reads and allocation failures cancel the candidate without publishing partial geometry. The per-generation owner closes files on cancellation, retirement and normal process termination; the Windows temporary-file facility also removes them after process termination.

Both local and terrain pressure decoding use admitted native chunks for source vertices/triangles, with bounded bulk reads. Decoded pressure texels use immutable native allocations and share identical byte blobs while retaining all material metadata. BGRA upload bytes are converted directly into a checked file in 64 KiB windows. Chunked native geometry avoids retained CRT arenas; the normal flat construction API remains available. CPU/spool vertices, indices, material order, keys and UVs stay exact.

Pressure GPU pages use bounded dynamic WRITEONLY DEFAULT buffers. Their shadow vertex layout contains position and UV (20 bytes); both compiled shadow vertex shaders ignore normals. The original 32-byte vertices remain available to GI, page keys and Reset replay. Each buffer creation samples current aggregate VA and retains the existing three-capacity growth allowance. DEFAULT is not a promise of zero host storage: DXVK static DEFAULT buffers retain staging, and dynamic direct mapping still consumes mapped host VA. The measured allocation reduction comes from bounded ownership and the smaller exact shader input. The mapping choice is visible in [DXVK v3.1.1 D3D9CommonBuffer](https://github.com/doitsujin/dxvk/blob/v3.1.1/src/d3d9/d3d9_common_buffer.cpp#L75).

Full geometry targets are admitted before pressure pages. DEFAULT render/depth targets use a separate 2 MiB host-metadata allowance plus the unchanged reserve and a 1 MiB contiguous witness; MANAGED probes retain their existing logical-byte budget. A three-backend meter at 3840x2160/MSAA8 observed no VA growth from 19 DEFAULT target/depth creations and their first use, including the current 1280/1024 shadow dimensions and 2048 stress targets. Screen effects retain their independent HRESULT rollback/retry path.

A separate pure page allocator control reproduces a further persistent 16 MiB mapped-pool cost on the second create/release cycle in DXVK 2/3, without textures, queries, locks, draws or our scene owners. Four cycles stabilize afterward; native D3D9 has no equivalent mapped growth. A full-scene DXVK 3 control with the ordinary reserve could build and publish at 307 MiB, then permanently defer Reset replay after that backend mapping appeared. Smaller padding, a native EVENT baseline and an extra retirement frame did not resolve it.

Recovery therefore has an explicit 240 MiB admission floor (256 minus one measured 16 MiB retained backend chunk), only for bounded page/cutout and DEFAULT target allocation while replaying the same committed BVH **and** upload plan after DEFAULT loss. Both identities are weak owners. A new BVH, a different plan with the same BVH, successful commit or full release cancels this allowance; failures retain retry ownership. Initial/build/new-generation policies and MANAGED probe admission stay unchanged. DEFAULT targets use the same scoped replay floor so recovery cannot stall before page replay begins. Every actual page creation samples current aggregate VA, with the same three-capacity request allowance. This is an admission policy floor, not a guarantee about post-Create VA: an opaque driver chunk can exceed the logical request.

The pressure plan retains its checked page and cutout backing file after publication. Reset releases DEFAULT pages, waits with a dedicated nonblocking EVENT query, then replays the same generation. Query failures and a five-second pending timeout use a bounded one-second retry; no FLUSH or blocking wait is added to the client path. Compatible MANAGED GI atlases survive pressure Reset and receive a full publication, including invalid cells and history. Exact-plan MANAGED cutout textures also survive; Reset preloads them without duplicating BGRA storage or creating replacement textures. A second Reset during target recreation or partial page copying cancels the candidate, preserves the same source scope and starts a new nonblocking fence. Pool compatibility prevents a normal generation from reusing unrecoverable DEFAULT pages, and idle DEFAULT pages cannot invalidate active MANAGED geometry.

## CPU evidence

`tests/validate_streaming_pressure.py` compares baseline `c03fec873602463265ada22c63990701514b445c` with seven real regions in four variants: flat baseline, bounded 434/395 MiB, and spooled 307 MiB. An old BVH remains retained through each replacement. Strict scene hashes include all texel bytes and material metadata; plan hashes read persisted BGRA through checked windows. Every scene, plan, page, batch, ray and occlusion result matches. Each variant exercises 57,344 rays. First-region counts remain 287,935 local triangles, 1,007,742 plan triangles, 82 pages and 3,666 batches.

The fixture's logical first retained BVH census is 23.00 MiB for pressure; the actual combined renderer fixture additionally accounts for the upload plan and a populated probe snapshot. Logical capacity counters are not exact VirtualAlloc reservation sizes. The CPU replay walks the address space on admission; its serial cache order and diagnostic overhead do not support a speedup or client frame-rate claim.

`test_temporary_geometry.py` covers checked file failures, allocation failures, cleanup and exact recovery. `test_material_texel_sharing.py` covers byte/metadata/ray equivalence, shared lifetime and accounting, three optional allocation failures, and owned/shared static-shadow alpha/hash parity. Paging/cursor and Store tests cover byte fidelity, compact strides, cancellation, compatible hits and pool transitions. Optimized and ASan/UBSan checks pass.

## Graphics evidence and reproduction

`tests/validate_world_cold_upload_gpu.py` runs the production renderer in an isolated x86 executable. It checks game absence through Toolhelp before every GPU process, hashes compilation inputs, binary, backend and real cache inputs, and rejects a prebuilt executable without matching provenance. The host PE thread-stack reserve/commit must match the client; a Zig default 16 MiB reserve is an invalid model for WoW's 1,500,000-byte reserve and produces artificial late-worker costs.

The actual-scene case creates 3840x2160/MSAA8 screen resources before pressure, builds the real scene under admission, publishes a nonzero serial and full 22-cubed GI atlas, preloads all six probe textures, and exercises real Reset/replay. The warm case retains an old real generation, injects index-buffer failure, checks rollback, and retries. Its 307 MiB entry is measured with that old generation already resident; it does not prove every replacement fits the approximately 260 MiB remaining after a cold 307 MiB entry.

All production phases precede independent DrawIndexedPrimitiveUP/readback raster comparison. The reference itself can allocate driver staging and must not contaminate the production pressure window. Initial geometry admissions use the 256 MiB policy; exactly scoped page/cutout Reset replay uses the explicit 240 MiB policy. A one-millisecond observer separately reports opaque driver transient minima and settled VA; Reset/Present may temporarily reserve worker/transfer storage. These are distinct from an unsafe renderer admission or a permanently deferred scene.

New DEFAULT buffers use NOOVERWRITE only while they have never belonged to a published drawable table. First publication clears that state on every committed page. Previously drawable or reused buffers retain synchronized Lock(0); normal MANAGED uploads keep their original lock flags. This avoids unnecessary synchronization on new DXVK mappings without allowing a CPU write to overlap an earlier draw. A flags-0 control stalled for about 24 seconds on a later Reset; the fresh-buffer control recovered in about 47 ms. Repeated Reset timing still varies with asynchronous driver work and bounded retry.

The final combined matrix passes all 18 backend/storage groups with one binary and frozen source/cache inputs: 18 actual-scene cases, 24 synthetic pressure cases, both pool transitions, query faults, six-Reset probe preservation and owner-scoped recovery policy per backend. Each actual-scene case performs three real Reset cycles. The 307 MiB cold case deliberately adds measured ballast after initial upload to leave approximately 248 MiB before Reset; this is a separate stress stage, not the original 307 MiB entry. Warm cases retain the old generation and inject index-buffer failure before recovery. All 82 nonempty page rasters and all 154 retained material textures (2,163,168 BGRA bytes) remain exact, with no replacement cutout upload on Reset. Probe tests interrupt recovery before the first page and during a partial copy, poison and verify the entire atlas/history, and replace incompatible descriptors.

No resource was admitted below its applicable floor. The one-millisecond observer still sees opaque DXVK Reset/Present reservations down to about 216 MiB in the controlled stress case. This is not an admission-floor guarantee after a driver call. The code preserves HRESULT rollback, retained-source retry, weak-owner cancellation and the ordinary reserve for new generations; it does not disable safeguards to force a partial scene through.

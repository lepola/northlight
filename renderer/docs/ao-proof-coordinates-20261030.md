# Fold fixed AO blur proof coordinates

AOBlur checks nine fixed bilinear footprints before its 25-tap silhouette-aware filter. The old loop reconstructs row/column indices with a division-equivalent multiply and floor for every footprint. Unroll only this fixed 3x3 scan, retaining row order, offsets (-1.5, 0.5, 2), the minimum reduction, threshold and all nine reads. The compiler folds the coordinates. The full filter, depth/water handling, RGB/HDR passthrough and AO kernels remain unchanged.

On the combined Microsoft SM3 assembly, the bright-centre proof body expands from 128 to 28 nontexture instructions, excluding control instructions; both versions still perform nine texture reads. These are emitted-code counts, not elapsed timings or a whole-pass/FPS improvement. Unrolling grows the static shader from 328 to 350 slots and 5,236 to 5,520 bytes, within the 512-slot contract. Temporary registers remain 16, and samplers remain s0/s1/s2/s3. The independent branch moves from 321 to 343 static slots and also retains 16 registers. No targets, sampler state, upload buffers, quality settings, memory reserves or admission limits change.

The independent branch retains its own original early-out; it does not import the combined-only dark-centre guard or Medium/Low kernels. Its bytecode therefore differs from the combined candidate. Every shader entry other than AOBlur is retained byte-for-byte within each branch. Approved blur hashes are updated only after the actual GPU comparisons pass.

Each branch passes 144 old/new FP16-output comparisons on native D3D9 and another 144 on DXVK 3: FP16/FP32 AO input, even/odd grids, nine authored patterns, HDR RGB, water, sky, near-threshold sparse occlusion and MSAA 0/2/4/8. All output bytes match and all outputs remain finite. A deliberately incorrect fixed-footprint shader is rejected by the combined DXVK image oracle. Each branch's original CPU blur/noise/mean/silhouette and AO-composition checks pass. The combined original AO-method and High/Medium/Low grazing/quality matrices also pass on both backends. This is functional acceptance, not complete scene/hardware or game FPS acceptance.

The reusable GPU comparison runner now requires --benchmark before creating timestamp/frequency/disjoint queries or repeating timing draws. Default comparisons submit one draw per shader/case and use only the existing completion EVENT. Benchmark selection is recorded in the report. A game-process guard runs before using the hidden test device. No game was launched, no new duration benchmark was run, and the generating client cache was not read or modified.

Reproduce CPU checks with tests/test_ao_blur.py and tests/test_ao_fold.py. Run tests/validate_ao_blur_equivalence_gpu.py without --benchmark, selecting the official native/DXVK backend and a private output directory. Use --baseline-ref d97ee4f7 for the combined candidate, or --baseline-ref 7871c40e for the independent branch. The compiled-source guard checks that all nine proof reads remain and that their loop/floor instructions are absent. Both branches build their own Windows x86 DLL.

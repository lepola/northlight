LocalFog и LocalFogCombine также побитово равны соответствующим старым .bin.

В области x=[780,1350), y=[0,550) все 313 500 RGB-пикселей результата
совпадают с сохранённым финальным кадром: максимум и средняя ошибка 0/255

поверхности шатра; несколько проверенных координат совпадают с глубиной

объявить причиной конкретную грань или нормаль.

исходного цвета пока не установлена. В захвате нет исходного WMO draw stream,

этот повтор не доказывает, что текущий исходный игровой draw создаёт тот же

Что уже исправлено в текущем коде и что проверено здесь

Текущий код уже содержит сокращение метаданных tracked snapshots, пропуск
повторных buffer uploads, отложенную CPU-очистку некритических снимков,
сокращение material pose/subdivision работы, специализацию native-normal
шейдера, отсечение невидимых ламп и пропуск state setup для полностью
переиспользованных кубов. Эти изменения нельзя выдавать за новые по этому QA.
HDR-оптимизации не объясняют именно этот старый SDR-сеанс.

На статическом сценарии арены visible-light selection оставляет 0..2 куба
вместо 5. При лимите 64 медиана времени completed по восьми ракурсам:
  D3D9: 0.031275 -> 0.011696 мс;
  DXVK: 0.030402 -> 0.011148 мс.
Сравнение выключает только visibility-aware selection в контрольном варианте
текущего кода; это не сравнение полной версии тестера с полной новой версией.
Статический прогретый проход здесь мал; динамические бой/персонажи отсутствуют.

Приоритеты дальнейшей оптимизации

1. Размерное admission для replay GPU cache. В текущем uploadReplay lambda
growthAdmission игнорирует запрошенный bytes и проверяет dynamicBudget(64 МиБ).
Получаются требования available=448 МиБ, largest=144 МиБ даже для малого
нового ресурса. Лог прямо показывает отказы replay-cache по largest при 79 МиБ.
Это конкретный кандидат на лишнюю работу через fallback. Перед изменением
нужны учёт суммарного роста в кадре, сохранение driver rename headroom и тест
под реальным фрагментированным x86 VA; просто подставить bytes недостаточно.

2. Проверить повторные очистки, не улучшающие largestFree. На застрявшем
79-МиБ диапазоне глобальная очистка не гарантирует появление большого блока.
Нужен отдельный эксперимент с ограничением повторной бесполезной работы и
мелкими размещениями, сохраняя отказ опасных аллокаций и критическое
освобождение ресурсов. Увеличивать общий размер кэшей на основании этого
лога не обосновано. Критические COM-release остаются синхронными и требуют
отдельного замера; отложенную некритическую CPU-очистку уже внедрили раньше.

3. В текущем игровом профиле разделить material UP/upload, pose fallback,
native draw и producer/replay sync wait. Счётчики DISPLACEMENT накопительные;
их большие значения сами по себе не доказывают стоимость кадра. Нужны
короткие одинаковые интервалы стояния, поворота и боя именно на арене.
Улучшение non-MSAA batching не следует переносить на этот MSAA-8 захват.

Для окончательного исправления ткани нужно зафиксировать исходный draw этой
поверхности до world effects: shader bytecode, VS/PS constants, VB/IB,
текстуры, depth/stencil и состояния; для пола — кадр с самим пятном и камерой.
Обычные Ctrl+Shift диагностические FGR в данном наборе этих native входов
не содержат. Выдуманная реконструкция native lighting не заменяет их.
